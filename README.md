# Formal sources of "Zeta functions and monodromy of degenerate hypersurface singularities over the positive rationals: least action and spectrum as dual readings"

This repository holds the formal sources of the article

> Agostino Russo, *Zeta functions and monodromy of degenerate hypersurface singularities over the positive rationals:
> least action and spectrum as dual readings*, preprint, 2026, [doi:10.5281/zenodo.24569077](https://doi.org/10.5281/zenodo.24569077).

It contains four things. The Q++ modules state the article's results. A generator writes the Lean 4 statements and proofs
of each module. The repository also has the generated Lean and the fixtures, which test each statement on exact rational
data.

## What is checked

Each numbered lemma, theorem and corollary of the article has *rows*, and Lean checks the rows. A row is a labelled
identity or inequality of the statement over the counts (the positive integers), the nonnegative rationals and the
positive rationals. Its Lean statement and proof are generated from the module, and Lean's kernel checks them.

For the theorems on zeta functions and monodromy, Lean checks only the rows. These are the rational identities of masses
and counts on which the residues and the multiplicities are read. The geometric, p-adic and topological steps are proved
in the article.

A cited fact that a proof uses enters the Lean as a theorem of Mathlib or as a hypothesis, never as an axiom. The proofs
use no axiom beyond `propext`, `Classical.choice` and `Quot.sound`.

## Layout

| Path | Content |
|---|---|
| `modules/M/M.qpp` | the module `M` in Q++, with the modules it uses (`uses`) |
| `modules/M/fixtures/` | the fixtures of `M`: exact rational data for its rows, with the expected verdict |
| `qpp/` | the generator (Python 3, standard library only); `qpp/README.md` is the reference of the language |
| `qpp/lean/` | the kernel of Q++ on Lean core alone: the counts as an inductive type, and the masses (the positive rationals) as pairs of counts |
| `qpp/closers/` | for each declaration, the tactic that closes each step of its generated proof |
| `lean/` | the Lake project: `QppModules/` (generated, one file per module), `QppBridge/` (the kernel read over Mathlib), `QppExamples/`, the axiom audits (`Axioms.lean` and the others), and the Palomar entry (`QppPalomar/`, `comparator.json`, `formalization.yaml`) |

Each row is stated twice in the Lean of its module, `lean/QppModules/Name.lean` (`Corner.lean` for `corner`). The first
statement, in the namespace `QppMathlib`, reads the row over the rationals of Mathlib and is proved there. The second,
in the namespace `Qpp.Modules`, reads it over the words of the kernel and is proved from the first through the bridge.

## Building

Lean 4 v4.35.0 and Mathlib v4.35.0 are pinned in `lean/lean-toolchain` and `lean/lake-manifest.json`. Run:

```
cd lean
lake exe cache get      # the build of Mathlib, from its cache
lake build              # the kernel, the bridge, the modules and the examples
```

## The Palomar entry

The entry for [Palomar](https://palomar-registry.org) is the module `modules/corner/corner.qpp`: its 61 rows, stated
over the rationals and the naturals of Mathlib. `lean/QppPalomar/Corner/Challenge.lean` imports Mathlib and Lean core
only, repeats the statement of each row as the library defines it and states its theorem with `sorry`;
`lean/QppPalomar/Corner/Solution.lean` imports the module, which proves them. `lake comparator`, under
`lean/comparator.json`, checks that the Solution proves the statements of the Challenge with `propext`,
`Classical.choice` and `Quot.sound` only. Both files and `comparator.json` are generated by `python3 -m qpp.modlean
--palomar corner`.

## Regenerating the Lean and checking the fixtures

From the root of the repository:

```
python3 -m qpp.modlean corner    # writes lean/QppModules/Corner.lean from modules/corner/corner.qpp
python3 -m qpp.modfix corner     # checks the fixtures of the module corner on its rows, in exact arithmetic
python3 -m pytest qpp/tests -q   # the tests of the generator, the printers and the checkers (pytest, no Lean)
```

The generated file is the committed one, byte for byte. `qpp/README.md` lists the other commands.
